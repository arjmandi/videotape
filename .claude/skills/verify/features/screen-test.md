# Screen test

`uv run scripts/screen-test examples/contrail --models wan3.0,minimax-h3,gemini-omni-flash-1.2 --stories terminal,posters --cap-usd 60`, run from the repo root, picks the model that draws Contrail best. It films the keys of the eight states in `SAMPLER`, which together show all ten element types, on each model in each story: two takes of each key, both filmed even when the first passes, and no move. Each model's takes in each story go into a tape of their own, `tapes/screen-test/<model>/<story>/` in the project, and the eye of each model, Qwen3-VL-8B and Claude, reads every take. Before any call it prints the estimate, and it stops before any call when the estimate passes the cap or an API key is missing. One cap holds for the whole screen test, and every call and read goes into the project's `ledger.jsonl`. It writes `tapes/screen-test/report.html` and prints the pick: the model with the most element types at the bar of 90% in every story, then the largest share of elements that pass every check, which decides while no type meets the bar, then the fewest invented controls, then the lowest cost. It never edits `pyproject.toml`. Run again, it films no take on disk and reads no picture whose read is cached, so the report is rebuilt for free.

Of the 96 takes planned, 95 were filmed and fal refused one for its content: wan3.0's take 2 of `search()` in posters, `VT409`, which the ledger counts at its listed $0.50. The ledger holds $42.54 against the $60.00 cap. By model, the takes and Claude's reads of them cost:

It wrote `examples/contrail/tapes/screen-test/report.html`. The first `--marks` run, on 2026-11-17, reused every take and read on disk and spent $0.00. The checks agreed with the user's marks on 34 of 60 elements, 56.7%, under the bar of 90%, so it made no pick. After the checks were fixed, they agreed on 38 of 60 elements of the same marks. The user then marked the 22 elements in dispute again, siding with the checks on each, and kept the first marks as `tapes/screen-test/marks-first.json`. On 2026-11-17 the run with the new marks agreed on 60 of 60 elements, 100.0%, spent $0.00, and printed `pick: gemini-omni-flash-1.2, with 2 of 10 element types at the bar of 90% in every story, 96 of 120 elements passing every check, 80.0%, 0 controls invented and $15.06 spent`. wan3.0 passed 56.7% and invented 87 controls, and minimax-h3 passed 55.8% and invented 22. `examples/contrail/pyproject.toml` names gemini-omni-flash-1.2 as `model`, set by hand. One key's answers from fal on each model, wan3.0's refusal and 16 of Claude's reads are kept in `tests/fixtures/recorded/`, which the tests replay. The estimate, the three refusals and the tests below were driven again after the run.

## Sub-features

- `screen-estimate` prints a line per model, its calls at its price on fal and its reads by Claude at the most a read of its picture size costs, then the total against the cap. `--estimate` stops there with exit 0 and needs no API key.
- `screen-over-cap` stops with `VT402` before the first call when the estimate passes `--cap-usd`, and names the cap the run needs.
- `screen-no-cap` stops with `VT402` before the first call when no `--cap-usd` is given.
- `screen-no-key` stops with `VT104` before any call when `FAL_KEY` is missing, and when `ANTHROPIC_API_KEY` is missing. Without the qwen extra it stops with `VT105` first.
- `screen-sampler` stops with `VT212` when the plan lacks a state that `SAMPLER` names.
- `screen-tests` is `uv run pytest tests/test_screen_test.py`, which runs the whole screen test on stand-ins with fal's names and prices: both takes of every key, the ledger, the rerun, one cap across the tapes, the report, the marks and the pick.
- `screen-every` is the render option the screen test films with, proven by `uv run pytest tests/test_render.py -k "every_films or keys_alone"`.
- `screen-paid` is the paid run. Costs money, and waits for the user's cap.
- `screen-rerun` runs the same command again after the paid run, and films and reads nothing.
- `screen-report` is what `report.html` must show.
- `screen-marks` is the calibration: a person ticks each element of wan3.0's terminal takes that is drawn right, downloads `marks.json`, and runs again with `--marks marks.json`.

## How to get to it (user POV)

- From the repo root, read the estimate first: `uv run scripts/screen-test examples/contrail --models wan3.0,minimax-h3,gemini-omni-flash-1.2 --stories terminal,posters --estimate`.
- Approve a cap at least the estimate's total, then run the same command with `--cap-usd <cap>` in place of `--estimate`.
- Open `examples/contrail/tapes/screen-test/report.html` from disk. It needs no server.
- Under Calibration, tick each element drawn right on each of wan3.0's 16 terminal takes, press Download marks.json, and run the same command again with `--marks <path to marks.json>`.
- Set the pick by hand: `model = "<pick>"` in `[tool.videotape]` of `examples/contrail/pyproject.toml`.

## Gotchas

- A take the model refused for its content, `VT409`, has no clip. The report shows it as `refused VT409` beside the other takes, counts it as the key's first take when its seed is lowest, and counts every element of its key as not drawn right, so a model is not rewarded for the takes it refuses. Its cost is the listed price the ledger counts it at. A key whose both takes are refused does not stop the screen test: the tape's other keys film, the record names it under `unfilmed`, and the report counts both refused takes. The calibration leaves a refused take out, since it has no picture to mark.
- The tapes under `tapes/screen-test/` cost money. Never delete them, their `takes/` or `looks/`, or their lines in the project's `ledger.jsonl`, or a rerun pays again.
- A screen-test tape holds keys and no move, so its `tape.json` has no hotspots and no search. Never play or publish it.
- The cap is the whole screen test's. Each tape renders under what the cap leaves after the other tapes' lines in the ledger, from this run and any run before, so a rerun with the same cap after a whole run spends nothing and fits.
- The estimate prices Claude's reads at `SIZES` in the script: 1280x720 for wan3.0, from the prototype run, 1344x768 for minimax-h3, and 1280x720 for gemini-omni-flash-1.2, which fal states no size for. The cap reserves each read at its picture's own size.
- In the paid run, Claude's reads of a model's takes cost $0.83 to $1.05, under a fifth of the most the estimate allows, since the estimate charges every output token a read may take.
- In the tests, a stand-in's two takes of a key are one picture when neither carries a flaw, so Claude reads the second from the tape's cache and the tests count fewer reads than takes. A real model's two takes differ.
- Qwen3-VL-8B can read a period the key does not draw at the end of a line, as in wan3.0's take 2 of `flight(CT 104, 2026-12-13)` in terminal, where it reads `1:30 PM to 11:40 PM, 7h 10m, 1 stop.` and Claude reads the line exactly. `tests/fixtures/recorded/reads/` keeps both reads. A period one reader adds to a line that has none passes `VT502` while another reader reads the line exactly, and fails it when every reader reads it, as `uv run pytest tests/test_checks.py -k period` drives.
- gemini-omni-flash-1.2 takes no seed on fal. A mark is of a take by its clip, and the report writes a take's picture again when the take is filmed again.
- A check names the element type it judges, not which element of that type, so the report places each check on an element by what it is about, as the script's `judged` says. VT503 judges the whole key and no element.
- The report keeps a person's ticks in the browser's storage; `marks.json` is what the script reads. A bad `marks.json` is an argument error, exit 2, as a bad flag of videotape's is.
- The report never names an absolute path, so a copy of the project rebuilds the same page.
