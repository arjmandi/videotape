# GPU render

`videotape render <dir> --model wan2.2-5b --checks qwen3-vl-8b --takes 3` makes Wan 2.2 draw every pixel of the tape, which needs one H100-class CUDA GPU. Wan2.2-TI2V-5B draws each scene's key from its own prompt, and Wan2.2-Fun-5B-InP draws each move between the two kept keys it is pinned to. `scripts/runpod-render <dir> --takes 3 --cap-usd <n>` rents that GPU on Runpod, copies the repo and any cached `tape/` there, renders, copies `tape/` back, deletes the pod, and appends a pod line to `<dir>/tape/ledger.jsonl`. `--dry-run` prints the whole plan and creates nothing. `--command` runs a different command on the pod in place of the render, and `--fetch` copies a different repo-relative folder back. On a Mac, `--model wan2.2-5b` stops with an `error:` line before writing anything. The dailies page shows the kept keys side by side, each move's seams, the render times, and the ledger totals in GPU seconds, pod hours and dollars.

## Sub-features

- `gpu-dry-run` prints the plan for the surf shop and for the cafe fixture without a key or a pod: GPU, price, cap, self-destruct deadline, image, disk, env names, create body, start command, setup and render commands. Exit 0, last line `dry run: nothing was created.`
- `gpu-dry-run-cafe-h200` prints the cafe fixture's plan for an `NVIDIA H200` at the price `--usd-per-hour` names.
- `gpu-cap-too-small` refuses a cap too small to render after the teardown margin with `error:` and exit 2.
- `gpu-dry-run-command` prints the plan with `--command` in place of the render and the `--fetch` folder copied back.
- `gpu-no-key` refuses a real run without `RUNPOD_API_KEY` with `error:` and exit 2, and refuses a directory without `screenplay.py`.
- `gpu-local` rejects `--model wan2.2-5b` on this Mac with `error: wan2.2-5b needs a CUDA GPU with about 80 GB, and this machine has Apple silicon (MPS) only; rent one with scripts/runpod-render`, exit 1, and writes no `tape/`. Without the wan extra it says `error: wan2.2-5b needs the wan extra; install it with uv sync --extra wan` instead.
- `gpu-smoke` is the first paid run: the cafe fixture with one take per shot, which draws three text-to-video keys and then three first-and-last-frame moves. Costs money.
- `gpu-full` is the paid surf shop run with three takes per shot, five keys and five moves, after which TapePlayer plays the tape with every journey from [player.md](./player.md) whose buttons the checks found. Costs money.
- `gpu-ledger` records one `take` line per filmed take and one `pod` line per pod session in `<dir>/tape/ledger.jsonl`, and `videotape dailies <dir>` rewrites the page with the totals.

## How to get to it (user POV)

- Run `scripts/runpod-render examples/surf_shop --takes 3 --cap-usd 10 --dry-run` from the repo root to read the plan.
- Export `RUNPOD_API_KEY`, then run the same command without `--dry-run`. Watch the pod id it prints, then the setup and render logs. When it ends, open `examples/surf_shop/tape/dailies.html` and `open clients/macos/build/TapePlayer.app --args examples/surf_shop/tape`.
- Run `scripts/runpod-render examples/surf_shop --cap-usd 4 --command "uv run videotape check examples/surf_shop/tape --checks qwen3-vl-8b"` to run another command on a pod and copy the tape back.
- Run `videotape render examples/surf_shop --model wan2.2-5b` on the Mac to see why it needs the pod.

- **Ledger.** After any render, `tail -n 1 <dir>/tape/ledger.jsonl` is a JSON object with `kind`, `at` and, for a take, `model`, `shot`, `mode`, `seed`, `seconds` and `gpu`, plus `request_id`, `duration` and `usd` for a take billed per call, or, for a pod, `pod`, `gpu`, `usd_per_hour`, `started`, `stopped`, `seconds` and `usd`. ## Gotchas

- A paid run starts billing when `pod <id> created` prints and stops when the pod is deleted. The script deletes the pod in its `finally` and confirms with a read. If it prints `NOT CONFIRMED DELETED`, open the Runpod console now.
- The pod arms a timer at boot that terminates it at the self-destruct deadline even if this Mac dies. Killing the script early still deletes the pod through its `finally`; a hard kill of the Mac does not, and then the pod runs until the deadline, which the cap paid for.
- A keyless dry run assumes $3.99/h, the secure-cloud list price read on 2026-11-09, unless `--usd-per-hour` names another price. With `RUNPOD_API_KEY` set, a dry run reads the live price and stock and still creates nothing. `error: no NVIDIA H100 80GB HBM3 with CUDA >= 13.0 in the secure cloud right now` means the catalog shows no stock. `--gpu "NVIDIA H200"` is the next option, at $5.29/h.
- A LOW stock reading in the catalog does not guarantee a pod. Twice on 2026-11-09 the H100 create failed after the plan printed, with `error: POST /pods -> 400: {"detail":"There are no longer any instances available with the requested specifications. ...` and exit 2. Nothing was created or billed. The retry that worked was `--gpu "NVIDIA H200"` at $5.29/h.
- The host CUDA floor is 13.0 because `uv.lock` pins torch 2.15.0, whose Linux wheels bundle the CUDA 13 runtime. The image's own CUDA version does not matter; the venv brings its own.
- The script copies `<dir>/tape` to the pod before rendering, so cached takes render again only when a prompt, key or setting changed. A changed key re-renders only the moves that start or end on it. Delete `<dir>/tape/takes` to force a full re-render; that costs money.
- The tape comes back in the failure path too, so a run that dies after some takes keeps them, and a rerun resumes from the cache.
- Every key renders before any move, so the pod loads TI2V-5B once, then Fun-5B-InP once. The first key take and the first move take include that load in their seconds and read long.
- Timings measured on an H200 on 2026-11-09: a text-to-video take took 80 to 105 s and a first-and-last-frame take 80 to 110 s, each including the checkpoint load on its first take. The surf shop's thirty takes ran on an H100 SXM on 2026-11-10: pod `n6lc3mo0get3jw`, 3141 s, $3.48 at $3.99/h, 2727.7 GPU seconds in the ledger. Its kept keys found `Enter shop`, `Create an account` and `Sign up`, but not `I have an account` or `Browse as guest`, and every seam was 0.040 or less. The cafe smoke's six takes are about 10 minutes of rendering, about $1.50 at $5.29/h with setup. Caps of $5 and $10 leave room. The cafe estimate is inferred from the measured take times.
- Keys render from text because on 2026-11-09 Wan2.2-TI2V-5B image-to-video moved its first frame by only 0.009 to 0.043, so a scene keyed by a move's last frame never appeared and its buttons were not found. Text-to-video keys with Fun-5B-InP moves between them moved 0.126 to 0.191, with seams of 0.004 to 0.005 at the start and 0.025 to 0.032 at the end, under the seam limit of 0.05. Lettering on those keys read back with a CER of 0.05 to 0.77 per line, so expect `fail:` lines on a Wan tape until the lettering improves.
- Only git-tracked files are uploaded to the pod, so `git add` a new screenplay or fixture before a paid run.
- SSH can take several minutes to answer after the pod shows `RUNNING`. Runs on 2026-11-09 printed 12, 48 and 78 status lines, the last one reading `RUNNING, ssh`. A small cap's deadline should leave room for that.
- A stalled rsync times out after 120 s, and the pod is still deleted.
- `ls` on this machine is aliased to a tool that prefixes icons. Use `command ls` when you assert on file names.
