# Variants test

`uv run scripts/variants-test examples/contrail --story terminal --cap-usd 40`, run from the repo root, measures which of three ways of drawing a scene's states keeps the scene's layout when only its data changes. It takes the results, flight and booked scenes, makes each scene's first state in walk order its base, drawn as a render draws it, `results(HNL, 2026-12-11)`, `flight(CT 500, 2026-12-11)` and `booked(CT 500, 2026-12-11)`, and draws the variants, the eight other results states and the flight and booked states of the six flights of 2026-12-12, by three methods. `seed` draws every state of the scene at seed 1, the base included, and the whole scene again at seed 2 when any state fails a check. `from-key` draws each variant from the base's key picture, image to video with the variant's own words, keeping the last frame as its key, with a second take only when the first fails a check. `repaint` would repaint only the text of the base's key on a model with a masked edit mode; gemini-omni-flash-1.2 has none, so nothing is drawn and the report says so, with its source. Before any call it prints the estimate, the least and the most, and stops before any call when the least passes the cap, when no cap is set, or when an API key is missing. The tapes go into `tapes/variants-test/<method>/<scene>/` in the project, one cap holds for them all, and every call and read goes into the project's `ledger.jsonl`. Every key gets the two readers' checks, and every variant the layout check, `VT505`, against its method's base: the key compared outside the text the readers found, by shading and by edges. It writes `tapes/variants-test/report.html`: the recommendation or why it is withheld, the layout check and its threshold, the methods side by side, what a fare change and a direction change would draw again under each method, each scene's keys method by method with their checks and costs, and the sources. The report shows each variant beside its base with a mark, the same layout or different, keeps the marks in the browser and downloads them as `marks.json`; `--marks marks.json` picks the metric and the threshold that agree with the most marks, judges every variant by it, and prints the recommendation, the method with the most variants whose kept take passes the layout check and every text check, then the lowest cost a passing variant, then the fewest keys and moves the two changes draw again. Without marks, or when the threshold agrees with fewer than 90% of them, the recommendation is withheld. Run again, it films no take on disk and reads no picture whose read is cached, so the report is rebuilt for free. `--model stand-in` runs the whole thing for free, with the stand-in's own reader.

The paid run has not been made. It waits for the user's cap, at least the estimate's least of $26.32 and up to its most of $52.64, which `--cap-usd 40` stops before the call that would pass it.

## Sub-features

- `variants-estimate` prints the selection, a line per method with its least and most calls, the model's calls at its price with the reads by Claude at the most a read of its picture costs, and the least and the most against the cap. `--estimate` stops there with exit 0 and needs no API key.
- `variants-over-cap` stops with `VT402` before the first call when the least passes `--cap-usd`, and names the cap the run needs.
- `variants-no-cap` stops with `VT402` before the first call when no `--cap-usd` is given.
- `variants-no-key` stops with `VT104` before any call when `FAL_KEY` is missing, and when `ANTHROPIC_API_KEY` is missing. Without the qwen extra it stops with `VT105` first.
- `variants-tests` is `uv run pytest tests/test_variants_test.py tests/test_layout.py`, which runs the whole variants test on a stand-in with gemini-omni-flash-1.2's name and price: both methods, the reroll and the retake, the ledger, the rerun, one cap across the tapes, the report, the re-render counts, the marks, the threshold and the recommendation, and the layout check's distances and its bar on pictures made up for the test.
- `variants-mode` is the first-frame mode the from-key method draws by, proven by `uv run pytest tests/test_hosted.py tests/test_standin.py tests/test_render.py tests/test_wan.py -k "first_frame or from_a_picture or from_another_keys or start_picture"`.
- `variants-standin` is the free run with `--model stand-in` on a copy of examples/contrail, which writes a report with no recommendation.
- `variants-rerun` runs the same command again after a run, and films and reads nothing.
- `variants-report` is what `report.html` must show.
- `variants-marks` is the marking: a person marks each variant the same layout as its base or different, downloads `marks.json`, and runs again with `--marks marks.json`.
- `variants-paid` is the paid run on gemini-omni-flash-1.2. Costs money, and waits for the user's cap.
- `variants-explain` is `videotape explain VT505`.

## How to get to it (user POV)

- From the repo root, read the estimate first: `uv run scripts/variants-test examples/contrail --story terminal --estimate`.
- Approve a cap at least the estimate's least, then run the same command with `--cap-usd <cap>` in place of `--estimate`. The cap stops a run before the call that would pass it; a run again with a higher cap resumes.
- Open `examples/contrail/tapes/variants-test/report.html` from disk. It needs no server.
- Under each scene, mark each variant's take the same layout as its base or different, press Download marks.json, and run the same command again with `--marks <path to marks.json>`.
- Try it for free on a copy with `--model stand-in`, which needs no key and no cap.

## Gotchas

- gemini-omni-flash-1.2 takes no seed on fal, so under the seed method a seed only names a take: the method draws each state on its own, as a render does today, and the report says so. The test runs it faithfully anyway, the whole scene again at seed 2 when a state fails.
- The from-key method starts every variant from the seed method's base at seed 1, `from-key/<scene>/base.png`, even when the seed method moved the scene to seed 2. A base whose seed-1 take was refused leaves the scene's from-key arm undrawn, and the script says so.
- The layout check has no threshold until a person marks pairs, so a first run's VT505 lines show distances and `no threshold yet`, every variant counts as passing the layout check, and the recommendation is withheld. The from-key arm takes a second take only when the first fails a text check, never for VT505.
- A mark is of a take by its clip, as the screen test's are. Marks of takes no longer on disk are counted and left out.
- The tapes under `tapes/variants-test/` cost money after the paid run. Never delete them, their `takes/`, `looks/` or `base.png`, or their lines in `ledger.jsonl`, or a rerun pays again. A free run on a copy writes nothing into examples/contrail.
- The re-render counts come from planning the project and an edited copy of it, for free, under each method's dependency rule: under from-key and repaint a variant's take depends on the base's key picture, so a change to the base's own words draws every variant of its scene again. The two changes the report shows touch no base, so the counts match across methods; `test_a_change_to_a_base_draws_every_variant_of_its_scene_again_under_from_key_and_only_itself_under_seed` proves the rule bites.
- The estimate prices Claude's reads at the most a read can cost, about $0.17 at 1280x720, where the paid screen test's reads cost about $0.03 each, so the real spend sits nearer the calls' price than the estimate's most.
- The cap reserves each call at the listed price and each read at the most, so a run under `--cap-usd 40` may stop with `VT402` before its last calls when every scene rerolls and every variant retakes; the resume it names continues for free where it stopped.
